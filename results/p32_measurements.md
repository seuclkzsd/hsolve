# P32：小主元统计、带状 LU 与 AVX-512 回代

2026-10-16，gpu02。**本轮未合入正式构建，整体目标仍未达成。** 最后一批 120 次完整对照均通过数值验收和本轮负载判据；最终缓存版六个算例的中位数仍全部高于同批调优 SLEPc，零点聚簇还明显慢于 P29。局部回代改进不足以采用整个后端。真实复数光子晶体及大型问题的既有缺口，本轮也未解决。

完整数据见 [p32_measurements.json](p32_measurements.json)，可审阅实现见 [p32_prototype](p32_prototype/)。正式源码没有接入本轮原型，四个生产二进制哈希保持 P29。

## 发现与实现

P31 私有后端把所有小主元情况统一填为 `FactorStats::null_pivots=1`。驱动按复数实嵌入约定将该值折算为近零方向数，并据此决定是否先移动工作位移。P32 在分解期间统计 D 块的小特征值数量，并按同一约定报告两倍数量；新增八组已知近零方向数的矩阵验证这一契约。

该修正确实修复统计接口，但零点聚簇问题仍有不同的判定：MUMPS 报告 3，驱动判为聚簇；私有带分解实际只测得 1 个小 D 特征值，修正后报告 2，驱动仍未判为聚簇。没有人为增加统计数来改变策略。原型仍把工作位移移出原位置，并在证书发现遗漏后追加迭代。

四个独立变体依次为：

1. **counts**：修正统计，工作分解和计数均沿用 P31 原生 Hermitian LDLH。
2. **lu**：计数仍用 LDLH，工作求解改用带状 LU。工作位移需要额外 LU 分解，惯性不由 LU 报告。
3. **lusimd**：替换 LU 的四右端前代与回代，使用 AVX-512 复数乘加；不足四列的尾部使用通用回代。
4. **lucached**：在分解时计算对角倒数，并直接按四右端行布局装载/写回，减少重复除法和打包；倒数溢出或下溢为零时仍使用标量复数除法。

所有变体保留快速残差检查、扩展精度原矩阵修正和延迟 MUMPS 回退。内部阈值 1e-12，独立验证仍对原始 A/B 分别计算扩展精度残差，采用复数模和 1e-10 阈值。带存储与主元交换顺序核对了 [LAPACK ZGBTRS 官方说明](https://www.netlib.org/lapack/explore-html/d1/dd7/group__gbtrs_ga4ae834536aaff26910f00f91444441ef.html)；SIMD 循环独立实现。

## 正确性与范围

四版各通过 **1540/1540** 次线性求解检查，合计 **6160/6160**。输入为相同的 240 个随机 Hermitian 矩阵、60 个广义矩阵对和 8 个统计契约矩阵，每个测试 nrhs=1、3、4、5、8；另有相同的 12 个秩亏构造，四版均被检测拒绝。重复运行不代表增加独立矩阵数量。

检查覆盖原矩阵残差、独立参考惯性、RHS 填充保护、只计数后解算状态失效及小主元数量。counts 最大分量后向误差 1.13e-12，三个 LU 版本均为 6.84e-13。每版各有 22 个随机输入使用过 MUMPS 回退，不能把全部通过归为纯原生算法成功。

完整求解共 **300/300** 次有效且 complete：18 次初步诊断、首批 150 次对照、最终 120 次对照、12 次新尺寸验证。240 份 hsolve 报告均通过其计数证书；60 份 SLEPc 报告均为原生 complex128 + LU。新尺寸验证沿用 P31 的独立 6000、24000、12000 阶输入，每个由四版各求解一次。

精确零主元导致分解提前中止时，当前统计仍只覆盖已处理部分，完整零空间重数处理也尚未补全。

这些实验没有完成生产后端全部接口资格。P31 已记录的通用重新分析、非 MUMPS 后端创建计数器的回退、内存预算组合和跨 CPU 分派问题仍需处理。本轮没有生产改动，因此未重复执行整套生产回归。

## 计时和负载判据

所有构建、数值验证和计时均在 gpu02，没有使用 GPU。性能为 CPU 16–31、16 个物理核、32 GiB、exclusive guard；构建和正确性诊断为 8–15、12 GiB。完整对照按求解器轮换顺序做五轮，保持原输入、原查询、原 k、tol=1e-10。hsolve 计 time_total_s，SLEPc 计 setup+solve+vectors，使用 P28 的调优复数环境。

本轮开始前固定了按线程的监测方式：每约 0.5 秒采样 CPU 时间增量；线程前后记录的 CPU 任一落在 16–31 或其超线程兄弟 48–63，就计入潜在测量核活动。外部活动合计达到 0.8 个测量 CPU，或全机外部活动达到 2 个 CPU，则该区间标为繁忙。监测器固定 CPU0，自身及受 guard 保护的后代排除。每次求解另记起止区间，整组所有求解器、所有五轮均通过时，才给该算例比较标为通过；没有删除单次慢结果来重新取中位数。

首次监测脚本使 guard 子进程继承 CPU0 限制，guard 在启动任何基准前拒绝。修复为对子进程恢复原可用 CPU 集合，再由 guard 绑定测量核；初始脚本和失败日志保留。

首批记录到两个超阈区间，涉及零点聚簇与十万阶近奇异，因此两组仅作诊断；另外四组完整通过。最终批次没有超阈区间，全部 120 次通过判据。周期采样仍可能漏掉短命或迁移线程，不能解释为操作系统级独占保证；P31 的旧数据没有重新分类。

缓存版相对 SIMD 版在零点聚簇、宽谱、十万阶近奇异和广义聚簇的端到端中位数降低约 5%–8%；另外两例没有收益。相对 P29，宽谱约降 42%、万阶近奇异约降 40%，但零点聚簇约增加 75%。最终六例中位数均高于 SLEPc，差距从宽谱的约 2.6% 到零点聚簇的约 4.37 倍；接近噪声范围的小差距也不能视为已达到“不慢于”。

零点聚簇仍处理 248 个右端、做 8 次分解；P29 为 148 个右端、5 次分解。缓存优化没有改变这一额外迭代。十万阶近奇异的 SIMD 回代及修正约 1.152 s，缓存后约 1.010 s，完整求解仍约 1.847 s，而 SLEPc 约 0.976 s。阶段时间为各自中位数，不要求相加等于总时间中位数。

后续需要优先处理原工作位移与主元稳定性，减少额外迭代和修正；同时保留对完整问题的计数验收。带状 LU 需要额外分解、较多存储与回代运算，继续优化局部回代不能单独填平全部差距。P28 的真实复数与大型计数瓶颈仍属整体目标的一部分。
