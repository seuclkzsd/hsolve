# P38：稀疏部分 Bloch 分解与自适应候选

**全部不慢于开源方案的目标仍未达成。** 本轮在 gpu02 CPU 上实现两个部分周期候选版本，保留原矩阵验收和 exact 证书。生产仍为冻结 P29。数据见 [p38_measurements.json](p38_measurements.json)，源码和复现脚本见 [p38_prototype](p38_prototype/)，实现差异见 [p38_candidate.patch](p38_candidate.patch)。

## 结构与实现

从实际 CSR 的第一行提出周期/边界相位，再逐行检查整个 A 和 B 的扭转平移关系。识别器不读取算例名、网格元数据或参考谱，支持 3–64 的整除周期。杆状光子晶体识别出周期 15，将 10125 阶问题分解为 15 个 675 阶稀疏子问题；重构误差为原矩阵无穷范数的 3.158e-17。球状输入的 B 不满足共同周期，继续原路径；均匀 Bloch 仍优先使用既有 P29 解析候选。

| 版本 | 行为 |
|---|---|
| partial | 每个子问题请求 k+2 对，按距原目标的距离合并候选 |
| adaptive | 每个子问题先取 2 对，仅对末尾候选仍落在当前选取半径内的子问题扩大请求，翻倍至 k+2 |
| control | 冻结 P37 control 库上重新编译原 P35 definite，关闭新路径 |
| native / base / scalar / dd | 冻结 P37 control、P29、P37 scalar、P37 dd CLI，作为计划的比较控制 |

子问题只生成候选；其值不作为严格排除其他谱值的证据。提升回原空间后，仍在原 A/B 上执行 Rayleigh–Ritz、满秩及不超过 0.5×原 tol 的准入检查，再执行原最终残差与精确 Sylvester 计数。缺对时使用原驱动补算。子问题使用显式迭代方法避免递归进入结构识别；自适应版内层数值失败退回普通候选路径。

求解器不将稀疏矩阵稠密化。仅稠密存储 Ritz 向量和小投影问题，Fourier 子矩阵继续使用 CSR。先核算候选内存预算，内部求解继续使用原进程预算与内存规划。

## 正确性与工作量

本轮记录 119 次完整求解，119 次有效，参考状态为 {'consistent': 6, 'complete': 113}。其中自适应版 91/91：11 个新增测试、60 个压力输入、9 个原生后端回退契约、9 个常规输入、2 个 65536 阶输入。两个大输入显式预算为 0.8 GiB。

新增 11 个输入阶数为 108–420，按 DESIGN 的小矩阵测试例外，用独立完整稠密谱验收。覆盖正/负/π 相位、多个周期、HEP/GHEP、稀疏 HPD 质量阵、A 或 B 被扰动后拒绝结构、显式迭代方法和关闭证书时的原路径，以及丢掉一个已求特征对后的补算。partial 和 adaptive 的这 22 次求解全部通过完整参考谱与预期路径检查。另有 6 次常规初版对照，全部通过。

自适应版完整 C++/MPI 回归：71 次调用，1104 通过、16 跳过、3 禁用、0 失败。包括 64 个普通程序、2 个线程/亲和设置、4 个 MPI rank 布局及 1 个 MPI CLI 检查；计数包含不同设置下的重复测试身份，OMP2/OpenBLAS1，GPU 隐藏。

杆状主案例的 adaptive 执行 20 次子问题求解，累计请求 50 对候选，内层共 20 次小矩阵分解、550 个 RHS；初版为 15 次子问题求解、累计请求 180 对。主对象由 3 次分解变为两次原矩阵证书计数，但不能省略内层工作量来描述整个过程。

外层 time_total_s 和 time_iterate_s 包含所有内层计算；主对象 factor_stats 只统计主对象。因此内层分解、回代及求解记录单独保留在 stderr 和 JSON。两个物理光子晶体仍只有不完整外部参考，标为 consistent；P37 的局部窗口补充检查没有将其改为完整独立参考。

## 性能比较状态

计划对 P29、冻结 P37 control、P38 control、P37 scalar、P37 dd、partial、adaptive 和 SLEPc 进行 9 个算例、各 5 次交错比较，共 360 次。CPU16–31、16 个物理核、32GiB、exclusive guard；SLEPc 使用 P34 保存的原生 complex128 + LU 配置。hsolve 计包含全部验收与证书的 time_total_s，SLEPc 计 setup+solve+vectors，均排除进程启动和输入输出。

**正式计时未启动。** gpu02 持续有其他 CPU 作业，181.0 秒内未获得启动所需的 60 个连续空闲采样，监控返回 75。因此本轮没有合格加速比，不能声称部分 Bloch 候选比旧版或 SLEPc 更快；P37 残差候选也仍缺少合格性能对比。负载记录全部保留。

共享核诊断仅验证正确性与计算路径，耗时未用作速度胜负依据。已有 P36 合格数据仍显示零点聚簇、广义零点聚簇及两个物理光子晶体存在明显差距，见 [P36 报告](p36_measurements.md)。本轮未解决球状晶体、大型计数和所有其他未达标路径。
