# P20：压缩阈值筛查与短转置回代优化

2026-10-16，gpu02。拒绝三个 BLR 压缩配置：百万阶分解变快，但精化增加回代次数，总耗时上升。保留 3–16 行单、双右端的 AVX-512 转置回代寄存器实现。七例各七轮 A/B 的耗时比几何平均为 **0.995080**。百万阶同批 P20 / SLEPc 为 **1.1726**，**目标仍未达到**。

完整数据见 [p20_measurements.json](p20_measurements.json)，相对 P19 的改动见 [p20_candidate.patch](p20_candidate.patch)。原型、脚本、二进制、逐次报告与验收归档在本机和 gpu02 的 `/tmp/os2026-p20-results.tar`，排除矩阵与完整特征向量。

## 条件

全部构建、测试、计时和独立验收在 gpu02（双路 Xeon Silver 4314）执行。普通完整求解固定 `16-31`，16 个物理核、32 GiB；百万阶固定双插槽 `8-15,16-23`，总计仍为 16 核、32 GiB；微基准 `16-23`，8 核。计时持有 `guard.py --exclusive`。构建、测试、单独验收为 `8-15`、12 GiB；百万阶计时期间停止这些任务。

本轮旧版为 P19。百万阶 hsolve 两版均使用三进程启动器、公开 `--interleave-leader`。保留原目标、容差、缩放、零主元检测与适用的默认 exact 证书。hsolve 比较包含证书的 `time_total_s`；SLEPc 为 setup + solve + vectors，双方均不计进程启动、输入载入和输出。交替或循环移位运行，全部重复和异常留档。

## BLR 压缩：不采用

私有 LD_PRELOAD shim 仅对启用 BLR 的 MUMPS 对象临时覆盖 CNTL(7)，调用后恢复；BLR=0 的精确惯性计数对象不变。原生迭代精化、失败回退和最终验收均保持。日志记录有效阈值、缩放及零主元检测；公共 FactorOptions 仍是原默认值 1e-10，不能用该字段标记实验阈值。56 条分析/分解调用日志核对通过。未新增生产环境变量。

三个小算例各跑完整精度和 BLR 1e-6，共 6/6 验收通过。近奇异实数算例的 BLR 精化失败后按原逻辑回退完整精度；这是回退成功，不是 BLR 自身成功。随后百万阶四配置各两次，8/8 通过，均为完整参考谱验收，无压缩回退：

| hsolve-full | 52.441440 | 51.941295–52.941586 | 2/2 | 4.267e-11 |
| hsolve-blr-e10 | 57.348521 | 57.105661–57.591381 | 2/2 | 3.791e-13 |

## 转置回代与正确性

P19 已优化单、双右端的非转置路径。本轮把阶数 3–16 的转置路径已求分量保留在 AVX-512 寄存器中，结束时统一写回。按原 dot-product 分块使用置换指令取出连续分量，保持 FMA 分配到各 lane 的方式、归约加法树和标量除法顺序。避免逐个写回后马上重叠向量读取。单位对角线不读；其他阶数、列数、ISA 和默认路由边界不变。

三个初始私有原型分别为跳过空掩码、8 行以内寄存器、16 行以内寄存器，另有最终 3–16 行修正版。四版各 **17,600 次逐位检查通过**，覆盖上下三角、转置、单位/普通对角线、零尺寸、边界、偏移及 leading dimension，并检查有效输出、输入和填充区。各原型复用输入，不把总检查次数当作独立形状数。生产 OpenBLAS 对照测试补充 15 行边界；完整 C++ **1067 通过、13 跳过、3 禁用、0 失败**。

每线程 128 MiB 因子池，预热后四轮交错计时。64 个形状覆盖 1/8 线程、8–512 行、1/2 右端和转置/非转置。下表为候选/旧版耗时比几何平均，通常各线程数 32 个形状；small 补测各线程数 28 个形状：

|---|---:|---:|
| maskskip | 0.998483 | 0.995852 |
| dot8 | 0.985076 | 0.982944 |
| dot16 | 0.982935 | 0.976274 |
| nonunit | 0.986778 | 0.977215 |
| dot16_small | 0.883396 | 0.932777 |
| bounded | 0.981792 | 0.979019 |
| bounded_nonunit | 0.985645 | 0.981917 |
| bounded_small | 0.868266 | 0.907197 |

跳过空掩码的总体收益很小，未合入。初版 dot16 在 8/16 行微基准表现良好，也完成七例和 31 例验收，但随后补测发现 1 行慢约 41%–51%，2 行也有退化，因此最终把新路径限制为 3–16 行。small 补测覆盖 1–7、9–15 行，最多 262144 个矩阵，每线程因子池不超过 128 MiB；其内存驻留条件与原微基准不同，不能混合几何平均。修正版 1/2 行与旧版的微基准耗时比约 1.000–1.033，不能称为每个形状都零开销；3–16 行保持收益。修正版重新执行逐位对照、完整 C++、微基准和完整求解。原 dot16 的全部结果仍保存在 JSON 与归档中。nonunit 指普通对角线补测。微基准收益不能解释为端到端收益。
