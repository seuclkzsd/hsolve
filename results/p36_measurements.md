# P36：右端打包、SIMD 分解与已检查因子复用

**尚未达到“全部不慢于最快开源方案”的目标。** 本轮在 gpu02 双路 Xeon Silver 4314 的 CPU 上完成实验，生产版本仍为 P29。私有源码、构建命令、完整测试和比较结果均已保存，没有提交或推送。

数据见 [p36_measurements.json](p36_measurements.json)，源码和复现脚本见 [p36_prototype](p36_prototype/)。[p36_candidate.patch](p36_candidate.patch) 记录相对 P33 原生后端的内核和打包变化；最终因子复用的增量在 [checked_reuse.patch](p36_prototype/checked_reuse.patch)。这些文件基于 P35 cappednative 私有库，不能单独当作生产补丁。

## 候选与控制

| 名称 | 相对控制的变化 |
|---|---|
| P29/base | 冻结的现有生产版本 |
| native | 冻结的 P35 cappednative |
| control | 保留原算法的重新编译版，区分编译布局与功能变化 |
| fused | 四 RHS 的缩放、置换、行布局打包及回写合并，去掉两次额外转置 |
| simd | fused 加 AVX-512 复数 Schur 更新；主元选择、交换、对角存储和异常回退仍检查 |
| reuse | simd 加同一位移的已完成分解复用，仍执行原有四 RHS 试探及原问题残差验收 |

复用只保留 status=0、因小主元检测被暂时拒绝的完整因子。普通 solve 在试探激活前仍拒绝使用；只有 alpha/beta 相同的检查路径可激活它。试探要求分量后向误差不超过 1e-12、每个 RHS 的相对残差不超过 sqrt(eps)。试探失败释放因子，精确奇异、独立计数失败和全结果恢复继续走已有回退。

原生调度范围保持为图结构筛选后的窄带复数精确求解；其余输入保留原路径。SIMD 的 FMA 可能改变舍入和主元轨迹，因此不能只靠打包输出一致性证明整条求解路径正确。所有候选保持原 k、容差、最终原问题残差与精确证书要求。

## 同机完整求解计时

正式批次固定 CPU 16–31、16 个物理核、32 GiB、exclusive guard，9 个算例、7 个版本、每版 5 轮交错。SLEPc 使用已验证的 P28 原生 complex128 + LU 逐例配置和 P29 Bloch 配置。hsolve 计完整 time_total_s，含检查及证书；SLEPc 计 setup+solve+vectors。双方均排除启动和输入输出，CLI 墙钟另存。SLEPc nearest 不执行同一惯性证书，但按同一原问题和容差独立验收。

启动前要求连续 60 个空闲采样。运行期目标核及其超线程兄弟累计外部负载达到 0.8 CPU，或全机达到 2 CPU，则标记繁忙。记录 3 个繁忙区间；7/9 个完整组满足全部 35 次有效且未命中繁忙采样。周期 /proc 采样不能证明操作系统级独占，所有采样保留。

## 归档、范围与后续缺口

共记录 635 次完整求解，635 次有效；有效参考状态为 {'complete': 557, 'consistent': 78}。生产 definite.cpp 和四个生产产物哈希未变。初始 continuation 返回 75 是为追加 reuse 候选主动延后计时，先前两套回归已经成功，并非数值失败。

所有编译、数值检查与性能求解均在 gpu02 进行。本地仅编辑、解析日志和核对归档。候选使用 -march=native，当前是 gpu02 私有原型；生产集成仍需独立模块、运行时指令集分派及通用路径。原生结构覆盖之外的真实光子晶体、大型精确计数和其他输入仍有性能缺口。

本机及 gpu02 保存 `/tmp/os2026-p36-results.tar`，452300800 字节、11693 个成员，SHA-256 `b33073cfe22d129d4876da82e93dedddb028082eec84f6b039b1157fe413940e`。下载后核对整个归档及全部 11692 个内容成员。包含源码、二进制、构建命令、线性输出、C++/MPI 日志、完整求解报告、负载采样、工具快照和输入哈希。沿用的 P33/P34/P35 输入保存在各轮归档或共享输入树，本轮没有生成新数值输入。比较工具按原流程在独立评估后删除特征向量。

复现依赖已有 P29 checkout、P35 cappednative 库、P33/P34/P35 输入与 P28 SLEPc 环境。脚本包含固定路径，重跑必须另建输出目录和 tag。报告没有将共享核诊断时间用于加速比，也没有声称已超过最快开源方案。
