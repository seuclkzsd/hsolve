## 算法与适用范围

输入只有实际 CSR 矩阵 A、B 和用户目标。识别器先从首行的列索引推导三维尺寸，再检查**所有行的列位置、非零数及数值**。B 必须为正对角、各分量块内常数，或单位阵。支持的自然边排序为：

- x 分量块：`(Nx, Ny−1, Nz−1)`；
- y 分量块：`(Nx−1, Ny, Nz−1)`；
- z 分量块：`(Nx−1, Ny−1, Nz)`；
- 三个维度均不少于 3，块内最后一维连续。

归一化矩阵的系数由实际横向邻接条目除以对应 B 对角元得到。对每一行验证对角、同分量邻接和全部交叉分量项，误差门槛固定为 `128 × epsilon × 最大模型系数`。此门槛只用于生成候选，不作为精确可分离性或完整性的证明。结构、质量矩阵或目标不符合时走原求解路径。没有按文件名、算例标签或维度表分派，也没有读取参考谱求解；独立参考只供测试验收使用。

对节点到单元的差分 D，节点正弦基映射到单元余弦基。在模态 m 上，归一化 curl-curl 的小块为 `||s||² I − s sᵀ`，其中 `s_d = 2 sqrt(alpha_d) sin(m_d pi / (2 N_d))`。三个波数非零时取两个横向极化向量；恰好两个非零时取零波数方向的一个极化向量。以 `B^(-1/2)` 恢复原问题坐标。目标球接触零空间或目标边界截断重根组时拒绝候选路径。

候选生成后仍计算实际 `A X`、`B X`，执行秩揭示 Rayleigh–Ritz，并按原问题后向误差检查。秩不足 k 或任一误差超过原容差一半时，丢弃候选并执行原数值分解和 Lanczos。通过时只省去主数值分解和 Krylov 迭代；已有符号分析、内存规划、最终验证、双精度 Sylvester 计数、缺对重跑及最终成功条件保留。模型谱只为计数端点提供提示，完整性由实际矩阵的精确计数决定。

本原型从 P20 库构建，不依赖 P21 的固定 BLR 算子。候选路径目前只在 exact 证书模式下启用，其他模式沿用原算法。

## 同批性能对照

所有构建、求解、数值验证均在 gpu02（双路 Xeon Silver 4314）。百万阶固定 `8-15,16-23`、16 个物理核、32 GiB、独占 guard；期间停止所有其他构建和数值工作。原目标为 `k=10, sigma=52.898884876721574`，矩阵阶数 1,027,733，原容差 1e-10。

hsolve 使用三进程、`--interleave-leader`，两个计数器各 8 核。SLEPc 使用 `results/p19_slepc_profiles.json` 的 4 进程 × 4 线程配置：ParMETIS、BLR 1e-11、ncv=3k、nev=k+2、内部 EPS 容差 1e-12；三个确认运行的 `unused_options` 均为空。

计时为 hsolve 完整 `time_total_s`，包括精确证书；SLEPc 为日志中的 setup + solve + vectors。均不含进程启动、输入和输出。原始比较表的 hsolve 配置说明使用共用模板；实际控制/候选由求解器名称和命令区分，汇总 JSON 的 `configuration_sources` 已明确各配置含义。

## 正确性、故障注入与未解决回归

- Python 推导验证：12 个随机尺寸、随机物理系数的 HEP/GHEP 网格，与小规模独立稠密广义特征值解比较；另检查条目改动、随机重排和零空间请求的拒绝，共 48 项通过。
- C++ 完整求解：8 个新的随机网格 × 5 种输入/目标，共 40/40 通过。8 个原矩阵接受候选；32 个对称条目扰动、随机重排、非均匀质量矩阵或部分重根目标均按预期拒绝候选并通过原路径。40 次全部通过独立稠密参考和 exact 证书。
- 现有算例：5 例 × 原版本/原型共 10/10 通过，覆盖规则网格、扰动腔体、复数 Bloch、近奇异位移。腔体的独立完整性为不完整参考下的 `consistent`，其余为完整参考下的 `complete`。这一组在 8 核、12 GiB、非独占验收槽运行，不用于可靠性能差异结论。
- 缺对注入：在 1 万阶、10 万阶上，各运行正常候选和删去一个候选后再计数，4/4 最终通过。注入后精确证书发现缺对，原分解/Lanczos 路径补齐；算子应用分别为 24、20。证书没有因候选来源而跳过检查。
- 私有库重新链接七组相关 C++ 测试：134 项中 **133 通过、1 失败**，涉及 driver、窗口/簇、计数故障、内存及并行会话。失败项为 `DriverAutoPrecision.AutoTakesSingleFactorsWhenOnlyTheyFitInCore`：它预期保持单精度，但实际因证书失败转双精度并使用 out-of-core，最终结果仍通过数值验收。

为区分基线问题，保留首轮失败后分别重跑整组 12 项测试：未修改生产版本 11/12，候选关闭 12/12，候选开启 11/12，失败均为同一项。生产日志同样报告 71 MB 计数估计超过预算余量，随后走回退。此结果证明原版本也能出现该失败，不能据此宣称原因已解决，或将候选回归标成全通过。没有通过删除测试、改变断言或反复重跑取通过值处理它。

全部 CLI 求解合计 **67/67 最终验收通过**，与 C++ 回归的失败分别统计。两次实验脚本设置错误也保留：首次 Python 检查漏写 `cases/` 目录，48 项性质检查已通过后读取正式输入失败；首次随机比较传入了不受支持的字面通配符，尚未启动求解器。修正后分别正常完成，不将这些启动错误算成求解性能点。
