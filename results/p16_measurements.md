# P16：面板向量化与百万阶迭代参数实验

2026-10-16。**本轮没有采用新的求解器优化。AVX-512 面板改写通过正确性检查，但七例完整求解的耗时比几何平均为 0.9988，尚无稳定收益；扩大块宽、扩大基底和初始向量过滤也未提供足够的采用依据。** 保留实验工具和全部正、负结果，求解器及默认 MUMPS 与 P15 相同。

逐次数据、完整求解验收摘要、命令和日志见 [p16_measurements.json](p16_measurements.json)。本轮仅保留 [blocktune_sweep.cpp](../bench/blocktune_sweep.cpp) 的实验功能，独立差异见 [p16_candidate.patch](p16_candidate.patch)。原始报告、逐特征对验收、实验源码及日志归档为 `/tmp/os2026-p16-results.tar`，本机和 gpu02 各一份；单独保存的实验二进制和完整求解的特征向量仍保存在 gpu02 的 `/tmp/os2026-p16`，不包含在该归档中。

## 条件与比较范围

全部编译、探针、计时和验收在 gpu02（双路 Xeon Silver 4314）进行。普通计时为单插槽 `16-31`、16 个物理核、32 GiB、`guard.py --exclusive`。百万阶迭代筛查为双插槽各 8 核：`8-15,16-23`，总计仍为 16 核、32 GiB；该阶段停止构建与验收道任务。构建、探针和独立验收使用 `8-15`、12 GiB。

完整求解的原始目标、容差和适用的默认 exact 证书保持不变。计时使用报告的 `time_total_s`，排除进程启动和文件读写。以下迭代筛查复用同一次分解，**不计分析、分解和精确证书**，不等同于完整求解对照。各筛查独立成批，不能把一批的基线时间与另一批的候选时间拼接比较。

本轮没有重测 SLEPc。最近的直接对照仍是 [P15](p15_measurements.md)：腔体 hsolve 0.224234 s / SLEPc 0.214029 s；百万阶 Yee hsolve MPI 53.060056 s / SLEPc 50.976600 s，分别慢 4.77% 和 4.09%。**“所有算例不慢于开源方案”的目标尚未达到。** 仓库调优的 SLEPc 对照也不代表已覆盖所有开源实现。

## MUMPS LDLT 面板向量化：不采用

通过单独的 `LD_PRELOAD` 实验库替换 MUMPS 5.8.2 的实数 `DMUMPS_FAC_MQ_LDLT` 单主元路径。AVX-512 同时更新 1、2 或 4 列，复用加载的行向量；乘法与减法分别执行，关闭 FMA 收缩，保持原标量运算顺序。双主元路径直接交给原 MUMPS。默认库、构建脚本及预载设置均未修改。

探针直接调用安装的原始 MUMPS 函数与候选函数，比较整个输出数组（包括填充区）、最大值及输出标志。三个列宽各 2574 组，共 **7722/7722 逐位一致**。覆盖 1/2/8 线程、向量尾部、零尺寸、OpenMP 阈值 300 两侧、Schur 排除区和不同已消元偏移。输入为有限的确定性数值，探针只覆盖单主元；这不构成任意浮点输入及所有 MUMPS 路径的证明。

固定排序的单次惯性计数筛查中，腔体的局部改善较大，百万阶只有约 0.7%。该筛查的 width=0 基线也经过转发拦截，且每项仅一次，不能作为完整求解收益。随后使用无拦截的 P15 CLI 为基线，与 4 列 AVX-512 候选做七次交错完整求解：

| 算例 | 基线中位数 s | 面板候选中位数 s | 新 / 旧 | 独立验收 |
|---|---:|---:|---:|---:|
| cav2d-rect-pert-1e5 | 0.216248 | 0.214268 | 0.9908 | 14/14 |
| ss-qa8fk-qa8fm | 1.342841 | 1.340682 | 0.9984 | 14/14 |
| syn-mem27-46 | 1.917183 | 1.901622 | 0.9919 | 14/14 |
| wg-halfslab-1e4 | 0.072300 | 0.073621 | 1.0183 | 14/14 |
| wg-square-1e5 | 0.440178 | 0.438380 | 0.9959 | 14/14 |
| yee-pec-box-1e5 | 2.279953 | 2.284531 | 1.0020 | 14/14 |
| yee-photonic-rods-1e4 | 0.809865 | 0.805445 | 0.9945 | 14/14 |

**98/98 独立验收通过，七例耗时比几何平均 0.998798。** 没有一例超过 3% 的中位数加速。此次改写不进入默认实现，原型与构建日志仅作实验留档。原型标注了 MUMPS 原版权及 CeCILL-C 许可，许可文本同时归档。

## 百万阶块宽：默认 8 列仍最好

`yee-pec-box-1e6`，固定 ordering=10、默认自动基底、原始残差容差 1e-10、接受余量 0.5，每种配置两次交错。下面时间仅为迭代阶段，回代量按右端向量数统计。

| 块宽 | 迭代中位数 s | 回代向量数（逐次） |
|---:|---:|---|
| 4 | 11.2093 | 76 / 76 |
| 8 | 10.5837 | 120 / 120 |
| 12 | 10.6566 | 156 / 156 |
| 16 | 11.8718 | 208 / 192 |
| 24 | 13.8988 | 264 / 264 |
| 32 | 16.9342 | 352 / 352 |

增大块宽使每个向量的算子应用成本下降，但额外回代抵消了收益。保留默认规则。

这组使用增强前的 P15 block benchmark，接受余量在源码中固定为 0.5。该版源文件已归档，但其 ELF 未在重建前单独保存。后续三组使用分别保存的 `bench-block`、`bench-start`、`bench-purified`，哈希见 JSON。

## 更大基底：重启减少，回代没有减少

固定块宽 8，每项两次。自动基底的首轮大小为 64。

| 请求基底大小 | 迭代中位数 s | 回代向量数 | 重启次数 |
|---:|---:|---:|---:|
| 自动 | 11.0798 | 120 | 2 |
| 80 | 10.8643 | 120 | 1 |
| 96 | 10.8168 | 120 | 1 |
| 128 | 11.2173 | 128 | 0 |

80/96 的两次中位数略低，但第二轮自动基底为 10.3883 s，反而快于 80/96 的 10.4774/10.4990 s。样本少、范围重叠，且回代量未下降，不据此改默认值。128 消除了重启，却增加回代量和基底操作成本。

新增的逐次原始残差探测记录显示：默认配置的一个运行在 112 次回代时最大后向误差约 1.44e-10，120 次时为 3.73e-11。即使把内部余量从 0.5 放宽到 1，该次 112 回代仍不满足原始 1e-10 容差。本轮所有实际计时仍使用 0.5，没有改变求解器验收门槛。

## 初始向量过滤：计入构造成本后收益不足

使用与默认相同的随机种子和向量流。在迭代开始前构造过滤向量，构造时间纳入 `total_s`，额外算子应用记录为 `start_op_applies`。两组均为三次交错运行。

第一组固定块宽 8：

| 初始块 | 迭代及构造中位数 s | 含构造的回代向量数 |
|---|---:|---|
| 默认随机块 | 10.2119 | 120 / 120 / 120 |
| A × 随机块 | 11.1031 | 128 / 128 / 128 |
| Op(随机块) | 10.8794 | 128 / 128 / 128 |

第二组测试组合过滤 `random + sigma*Op(random)`，等价于精确算术下的 `(A-sigma B)^-1 A random`，希望减少零空间分量：

| 块宽 / 初始块 | 迭代及构造中位数 s | 含构造的回代向量数 |
|---|---:|---|
| 4 / 默认 | 10.2257 | 72 / 72 / 72 |
| 4 / 组合过滤 | 10.6809 | 76 / 76 / 76 |
| 8 / 默认 | 10.1216 | 120 / 120 / 120 |
| 8 / 组合过滤 | 10.0535 | 120 / 112 / 120 |

8 列组合过滤只有一次净少一块回代，另外两次把省下的回代用在了构造上；中位数只低 0.67%，尚无稳定采用依据。4 列则更慢。两个独立批次的默认 4 列回代数从 76 变为 72，说明停止位置也会受浮点和探测门槛影响，不能只比较某次最小回代数。

四组百万阶筛查共 **41 次迭代运行**，均收敛且最终最大后向误差不超过 5e-11；这些是 benchmark 内部检查，**没有完整精确证书与独立完整求解验收**，不计入前述 98 次有效完整求解。

## halfslab 诊断与交付检查

对 P15 的 `wg-halfslab-1e4` 另做一次 `memset` 拦截诊断。主要 DenseMatrix resize 的 14 次串行调用累计写入 11,103,384 字节，带拦截计时约 3.43 ms。该例 n=9801、p=1、ncv=47，48 列基底约 3.76 MB，小于 P15 并行初始化的 4 MiB 阈值；本次跟踪没有观察到大矩阵并行清零路径。尚不能把此前约 1.9% 的回退归因于并行清零，也不能声称已排除回退。这次诊断没有独立验收，不计入 98 次完整求解。

本轮只有实验工具代码进入工作区：增加探测历史、可配置的内部余量（默认 0.5）和交错初始过滤。最终 benchmark 编译成功；实数腔体和复数 Bloch 各四种过滤的 8 次冒烟运行均收敛、后向误差小于 5e-11，特征值与各自默认配置的最大相对差不超过 1.50e-13。此次冒烟同样不代替完整证书验收。

求解器二进制与 P15 完全相同，无需为实验工具改动重跑未改变的完整求解器测试。最终哈希：

## 复现示例

先停止双插槽核范围内的其他构建和验收，再运行：

```bash
cd /tmp/os2026-p10-repair.9doyhO
env/run.sh python tools/run/guard.py --exclusive --cores 8-15,16-23 --mem-gb 32 --timeout 300 -- \
  env LD_PRELOAD=$PWD/build/release/libhsolve_blashook.so /tmp/os2026-p16/bench-purified \
  --data /share/home/linzihan/p7_p7-membudget/data --p 4,8 --block-ncv 0 \
  --start-filter none,purified --original-tol 1e-10 --reps 3 --apply-reps 1 \
  --ordering 10 yee-pec-box-1e6
```

其他配置、面板原型编译、探针、完整求解与独立验收命令均保存在 JSON 内的原始 guard 日志中。
