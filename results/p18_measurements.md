# P18：八右端 AVX-512 回代与可选 NUMA 内存交错

2026-10-16，gpu02，双路 Xeon Silver 4314。保留八右端回代内核和显式 `--interleave-leader` 选项。最终百万阶三方对照中，新版 / 旧版耗时比为 **0.9786**，新版 / 本批调优 SLEPc 为 **1.0083**。腔体仍比 SLEPc 慢 **7.67%**，尚未达到所有算例不慢于开源方案的目标。

逐次数据、阶段耗时、独立验收和日志见 [p18_measurements.json](p18_measurements.json)，本轮相对 P17 的改动见 [p18_candidate.patch](p18_candidate.patch)。原始记录、源码、探针、包装器及二进制归档为 `/tmp/os2026-p18-results.tar`，本机与 gpu02 各一份；不包含输入矩阵和完整特征向量。

## 条件

全部编译、探针、测试、计时和独立验收都在 gpu02 执行。普通完整求解使用单插槽 `16-31`、16 个物理核、32 GiB；微基准为 `16-23`、8 核；计时均持有 `guard.py --exclusive`。构建与测试使用 `8-15`、12 GiB。百万阶以及 NUMA 小例实验使用 `8-15,16-23`，双插槽各 8 核、总计 16 核和 32 GiB，此时停止构建 / 测试道。

基线是 P15 求解器，P16/P17 未改默认数值求解器。每次完整求解保持算例原始目标与容差，适用的默认 exact 证书开启。hsolve 时间包含证书，为 `time_total_s`；SLEPc 为 setup + solve + vectors，双方均排除启动、输入加载与输出。基准顺序使用 AB/BA 或多候选循环移位，全部重复均保留。

## 内核实现与逐位验证

原 AVX-512 小三角回代每次处理最多四个右端。新实现对完整的八列组一次读取三角因子：转置路径保留八条独立累加链，仍用两次原 `reduce4`；非转置路径对阶数 64–512 的块先把八个右端排列成逐行连续数据，在至多 32 KiB 的栈缓冲中更新，然后写回。每个元素的除法、FMA 和归约次序保持不变，单位对角线不读取。

AVX2、portable 和不足八列的余数沿用四列路径。原有路由上限仍为 AVX-512 三角阶数 512、右端数 16，没有扩大适用范围。只重排右端，不打包因子；没有增加公开环境变量或改变停止条件。

第一版八列展开以及最终带右端重排的版本，分别通过 **13,376 次与旧内核的逐位比较**。覆盖上下三角、转置 / 非转置、单位 / 非单位对角线、零尺寸、向量和分组边界、64/512 阈值两侧、不同 leading dimension 与偏移，以及 AVX2 / portable 路径。单位对角线和未使用三角区放 NaN；检查输入不变、所有有效输出有限、前后及列间填充区不变。两版复用同组输入，不能把检查总数当作两倍独立形状。

同时扩展现有 `SmallTrsmMatchesRealDtrsm` 测试的阶数与右端数，直接对照真实 OpenBLAS 的结果。正确性探针与微基准不替代完整求解验收。

## 微基准：收益集中于八列以上

每线程 128 MiB 因子池，先预热，再交错计时四轮；八线程时各线程处理独立三角块。下表比较第一版八列展开与最终右端重排，单位为每线程每个调用的墙钟摊销微秒。

| 线程 | 阶数 / 右端数 / 转置 | 展开版 µs | 重排版 µs | 重排 / 展开 |
|---:|---|---:|---:|---:|
| 1 | 128 / 8 / N | 18.13 | 13.06 | 0.7201 |
| 1 | 128 / 16 / N | 34.22 | 23.77 | 0.6946 |
| 1 | 512 / 8 / N | 423.90 | 187.80 | 0.4430 |
| 1 | 512 / 16 / N | 825.37 | 347.94 | 0.4216 |
| 8 | 128 / 8 / N | 25.41 | 24.34 | 0.9576 |
| 8 | 128 / 16 / N | 38.70 | 29.31 | 0.7572 |
| 8 | 512 / 8 / N | 437.38 | 298.40 | 0.6822 |
| 8 | 512 / 16 / N | 838.64 | 449.18 | 0.5356 |

补充测量 64 与 256 阶边界附近形状也保存在 JSON 中。四右端、转置和不在重排范围内的形状主要是对照项，通常接近持平。这是局部内核收益，不能直接解释为完整求解加速。

另对原四列路径补测 48 个单 / 双右端形状。首次 32 阶、单线程、单右端的非转置与转置分别慢 52.7% 和 7.3%；追加 24/32/40 阶、每配置十轮交错复测后，该点的耗时比分别为 1.0125 和 0.9876，其余复测形状也未出现超过 3% 的中位数退化。首批异常与复测都留档，未据首批直接认定稳定退化。

另以真实 OpenBLAS 对照更大阶数：第一版在并行区域内的大转置回代有收益，但在并行区域外的大非转置回代明显更慢，因此没有全局提高小 TRSM 路由上限。该筛查用的是第一版，不能把它当成最终重排版与 OpenBLAS 的对照。

## NUMA：百万阶有效，小例不宜统一开启

只改变主进程的内存策略，helper 仍保持继承的策略。P15 MPI 二进制各两轮：

| 算例 / 求解器 | 中位数 s | 范围 s | 有效 |
|---|---:|---:|---:|
| yee-pec-box-1e6 / hsolve-before | 53.131171 | 53.123602–53.138740 | 2/2 |
| yee-pec-box-1e6 / hsolve-interleave | 52.059266 | 51.905989–52.212544 | 2/2 |

七个小例在相同双插槽 MPI 布局下各三轮，42/42 有效，交错 / 原策略耗时比几何平均为 **1.056868**。halfslab 约慢 43%，因此不作为统一默认策略。

新增 `hsolve-mpirun --interleave-leader` 从允许 CPU 的 NUMA 节点生成交错列表，用 `numactl` 只为 rank 0 应用策略。单节点时无作用；明确请求但无法应用时返回错误。默认仍保持原策略。最终百万阶实验直接使用公开启动选项，不依赖早期的实验性 rank 包装器。
